  <action>
Implement `ActionScopeHasher` using only JDK APIs. Normalize action type and target kind to uppercase enum/string values; reject null/blank message IDs; deduplicate; sort by natural string order; and produce versioned canonical UTF-8 bytes.

Use fixed field order and length-prefix every value as UTF-8 byte length, including every repeated message ID. Start with canonical version `scope-v1`. Hash with `MessageDigest.getInstance("SHA-256")` and encode exactly 64 lowercase hex characters. Do not use `String.join`, delimiter-only concatenation, Java serialization, map iteration order, or database array text as the canonical form.

Implement `ActionScopeService.createOrGet(accountId, actionType, targetKind, messageIds, targetSummary, riskSummary)`. Require positive account ID and a non-empty exact ID set, compute canonical IDs/hash/count, and persist one immutable scope. Put the insert in an injected `ActionScopePersistenceService` public `REQUIRES_NEW` method. Catch a unique violation only after that inner transaction ends, then reload `(accountId, hash)` and compare account/action/target/IDs exactly; throw a collision error on missing/mismatched data. Do not catch-and-query in the failed insert transaction.

Represent summaries as fixed records, not arbitrary maps. `ActionScopeTargetSummary` may contain only bounded display label, sender address/domain, and selected target count appropriate to target kind. `ActionScopeRiskSummary` may contain only non-negative protected/high-risk counts and a bounded immutable list of enum-like warning codes. Validate lengths/counts, reject unknown JSON fields on readback, reject nested caller objects, and serialize these records to the JSON columns. Subject/body/header/token text is not accepted by either type.

Return `ActionScopePreview` only from the persisted/reloaded row. Include scope ID, hash, exact count, immutable exact IDs for internal consumers, typed target/risk summaries, and created time. Deep-copy every list on construction and readback. UI-facing callers omit the ID list when rendering, and no preview value may come from a later query.
  </action>
