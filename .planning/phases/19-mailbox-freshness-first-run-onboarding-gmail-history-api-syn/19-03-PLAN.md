<objective>
Create the provider-neutral synchronization capability and implement the exact Gmail API surface: profile anchor, recent bootstrap, complete backfill, unfiltered History pages, current METADATA fetch, 404 classification, and metadata-only attachment ID membership. No worker concurrency is enabled in this plan.
</objective>

<threat_model>
ASVS L1; block high severity. Account isolation: every provider method receives a validated owned UserAccount and uses its managed client only. Token/error leakage: exceptions are classified to bounded codes; response bodies/tokens never enter logs or DTOs. Destructive refresh failure: provider stops on REAUTH_REQUIRED and delegates credentials to Plan 02 when available; it never removes accounts. Cursor tampering/replay: cursor types are capability-validated and history IDs parsed as BigInteger, never client parameters. Provider-body leakage: METADATA whitelist and source guards prohibit FULL/RAW/snippet/content. CSRF: provider methods are not web routes; later retry remains POST. Stale-rescan deletion: 404 is classified as HISTORY_EXPIRED and never directly deletes local rows or installs a new anchor.
</threat_model>
