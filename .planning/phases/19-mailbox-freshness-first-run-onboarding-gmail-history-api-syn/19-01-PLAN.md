<objective>
Deliver the production-quality end-to-end persistence tracer: a provider-neutral durable mailbox state, revision-aware metadata writes, and one atomic change-unit commit from provider-shaped input through PostgreSQL state. This plan intentionally remains single-lane; concurrent freshness/backfill execution is forbidden until this commit boundary is green.

Purpose: establish the correctness boundary every later History, backfill, rescan, OAuth, and UI slice consumes.
Output: V15 production migration, mapped entities, native atomic write repository, short transaction service, and Postgres tests proving replay, stale-write rejection, deletion, no-op checks, and guarded sweep behavior.
</objective>

<threat_model>
ASVS L1; block high severity. Account isolation: every SQL mutation and state lookup requires account_id and tests cross-account IDs. Token/error leakage: schema stores only bounded safe error codes/details, never token/provider bodies. Destructive refresh failure: V15 adds credential status without account deletion; manager wiring is deferred to Plan 02. Cursor tampering/replay: cursor kind/value and lease ownership are server-owned, numeric revisions are validated, and replay is idempotent. Provider-body leakage: metadata_snippet is cleared/removed and no body columns are added. CSRF: no route is added here; later manual retry/reconnect remains POST/CSRF protected. Stale-rescan deletion: generation sweep is high-risk and must require generation match plus no post-start freshness revision/update.
</threat_model>
