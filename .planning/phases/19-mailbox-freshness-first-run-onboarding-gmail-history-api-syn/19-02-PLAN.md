<objective>
Replace per-client network refresh with Spring Security's background authorized-client manager while making every failure nondestructive. Fix removal semantics before registering refresh failure handling, preserve nullable token timestamps and replacement-token omission behavior, and serialize refresh per provider account.
</objective>

<threat_model>
ASVS L1; block high severity. Account isolation: manager keys are registration ID plus providerAccountId and tests reject email/other-account substitution. Token/error leakage: tokens remain encrypted at rest and exceptions/UI-safe codes never include token endpoint bodies. Destructive refresh failure: this plan removes account deletion before failure handlers are enabled. Cursor tampering/replay: no cursor mutation occurs on credential failure; workers receive REAUTH_REQUIRED and stop. Provider-body leakage: Gmail client initialization receives only managed access credentials, not message bodies. CSRF: reconnect remains an authenticated OAuth flow; no unsafe GET mutation is added. Stale-rescan deletion: refresh failure cannot launch or complete a sweep and preserves all indexed data.
</threat_model>
