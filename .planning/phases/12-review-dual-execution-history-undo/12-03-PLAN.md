  <action>
Replace numeric-ID legacy routes with opaque action public IDs and server-issued
operation intents. Cancellation locks/reloads one owned action, allows only QUEUED or
BLOCKED, sets CANCELLED, appends `ACTION_CANCELLED`, resolves related open conflicts,
and returns the existing receipt on replay. It never deletes scope/action/history or
cancels executing/completed work.

Selected approval accepts a bounded unique set of explicit action public IDs plus one
opaque intent. Reject duplicate, foreign, stale, changed, conflicted, needs-decision,
non-queued, unsupported-account, or ineligible members before reserving any. Lock
accounts ascending then actions ascending. For selected unsubscribe actions, the
confirmation step must freshly re-inspect each candidate/method and bind a separate
unconsumed Phase 11 nonce into the expiring batch command token; a generic action
public ID is not irreversible consent.

Call `ExactScopeExecutor.executeBatch` once. Its shared
`ExecutionReservationService.reserveBatch` validates and reserves the complete set in
one transaction, commits all execution/target/lease facts, and then the executor
dispatches each reserved action independently through the same handler/completion path
as immediate execution. `ActionApprovalService` must not pre-create executions and
then call the singular executor, because that would create a second reservation path.
Post-reservation failures remain action-local and cannot misstate peers.

Eligible-all is a two-POST flow. First POST resolves the complete server-side eligible
set under the current authorized account/action/state/target filter, not the visible
page, and returns server-derived action/account/target plus excluded reason counts and
an expiring set fingerprint intent. Final POST recomputes under locks; any set change
returns stale confirmation with zero reservations. Enforce a named configured maximum
action count; over-limit returns 422 with narrowing guidance and never truncates.
Generic eligible-all excludes unsubscribe rows and reports
`FRESH_CONSENT_REQUIRED`; a dedicated confirmation may include them only after
issuing one fresh Phase 11 intent per candidate/method and binding the complete nonce
set into the final server token.

Test selected/all overlap, duplicate submits, cancel/reserve race, one invalid selected
member rollback, beyond-visible-page all approval, set-change invalidation, limit,
stable lock order, and independent post-reservation results.
  </action>
