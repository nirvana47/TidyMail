<objective>
Delete the five `h2` dialect branches in production repository code — collapse each ternary to the Postgres-only branch — now that nothing runs on H2. Pure deletion, not a rewrite: the Postgres branch is the one already exercised in production. (TEST-01; research §1.4, §7.1 step 3.) This is a one-way-door deletion (recoverable only via git/rewrite), so a `checkpoint:decision` precedes it.

Ordering guarantee: this plan `depends_on: [18-03]`, and 18-03 now migrates EVERY H2-consuming integration test onto the shared Postgres base (its final task proves zero non-migration H2 consumers remain and the full suite is green). So by the time this collapse runs, the last H2 consumer is already gone — collapsing the branches cannot red the suite (RESEARCH §7.1 "step 3 before 4; each step keeps the suite green"). 18-05 then merely deletes the now-unused H2 test-migration set + pom dependency.

Purpose: Remove the dual-dialect risk at the root (C-1/C-2/C-3) so a green test can never pass on H2 while production SQL differs.
Output: five repositories with no H2 flag, helper, or ternary; a repo-wide grep for H2 dialect branching returns zero in src/main; the full suite stays green on real Postgres.
</objective>
