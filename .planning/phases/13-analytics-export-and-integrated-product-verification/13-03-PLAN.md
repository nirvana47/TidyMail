Add validated property `tidymail.export.max-rows=50000`. Define typed
`FilteredCsvSource&lt;Q,R>` with `countOwned`, `streamOwned`, and fixed `CsvSchema&lt;R>`;
never accept raw parameter maps or entities. `ExportService` resolves owned accounts,
then runs count and stream inside one read-only `REPEATABLE_READ` transaction/snapshot

for stream consumption and closes the JDBC stream on client disconnect/write error.
Return bounded 422 when count exceeds cap before setting content type or attachment
headers; only after an in-cap count may the service set headers and stream through a
small buffered writer. Keep a defensive emitted-row guard, treated as an invariant
failure rather than normal cap handling; the shared snapshot must make it unreachable.

comma, CR/LF, deterministic header order, and spreadsheet formula defense. On the

treat leading tab or carriage return as dangerous, prefix one apostrophe, then retain
the original text and apply normal CSV escaping. Sanitize filenames to fixed
lowercase surface plus `YYYY-MM-DD` UTC and `.csv`; no query/account/sender input
enters filenames.

Test cap-1/cap/cap+1, a concurrent-insert attempt between count and stream proving
snapshot stability, prompt first bytes without list materialization, writer/client
disconnect closure, safe error copy before response commitment, all dangerous
prefixes, and exact headers. Spy that over-cap invokes no stream and writes no content
type, attachment, or body.
