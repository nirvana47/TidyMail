## Spacing Scale

Declared values:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline gaps, title/description stack gaps |
| sm | 8px | Button padding, small control gaps |
| md | 16px | Default card/category padding, compact row gaps, dense table/card padding, and page section gaps |
| lg | 24px | Page gutters and dialog inner padding |
| xl | 32px | Desktop main top padding |
| 2xl | 48px | Lower page padding and larger section breaks |
| 3xl | 64px | Reserved page-level spacing |

Exceptions:

- Interactive touch targets on rail links, category select controls, mobile buttons, Review controls, dialog controls, and row action controls must remain at least `44px` high or wide where applicable.
- Cleanup category rows should be compact: desktop sender rows target a `60px` minimum row height, while mobile may stack fields to preserve 44px controls and avoid horizontal page scroll.
- Left rail width remains `248px`; collapsed rail remains `48px`; content max remains `1180px`.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 | 1.5 |
| Label / table head / eyebrow | 12px | 600 | 1.3 |
| Category title / rail brand | 16px | 600 | 1.3 |
| Page heading | 30px | 600 | 1.15 |

Typography contract:

- Keep the mock's compact, polished scale. Do not enlarge cleanup pages into oversized card UI.
- Page titles must be visually dominant but lighter than a marketing hero; `30px/600` is the desktop target from current CSS and Build Notes. Responsive heading reductions may follow existing CSS behavior without introducing an additional design-token size.
- Category descriptions, sender addresses, domains, and secondary metrics use muted body text and must truncate/wrap without breaking the row layout.
- Long account email labels in the rail selector must stay within the rail using max-width, overflow hidden, and ellipsis/truncation behavior.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f4f6fb` / `#ffffff` | Page background and primary surfaces |
| Secondary (30%) | `#f8faff`, `#eef2ff`, category tints | Rail active state, subtle category backgrounds, compact panels |
| Accent (10%) | `#3f5cff` and cleanup attention `#c95020` / `#ea580c` | Rail active link, focus outline, primary settings controls, high-attention cleanup action buttons |
| Destructive | `#b83232` | Delete data/logout, delete warnings, destructive Review/cleanup confirmations only |

Accent reserved for:

- Active rail route and focus rings.
- `Settings` as the primary page control.
- Per-row cleanup action button, whose high-attention color remains consistent as label changes between Archive, Delete, and Mark as Read.
- Dialog primary actions.

Do not use accent colors to decorate numeric status badges in the rail; those badges must not be visibly rendered.

## Cleanup Page Layout Contract

Bulk Archive/Delete and Unread Only share the same quiet structure:

1. Shared rail with account selector.
2. Simple header with eyebrow, exact page title, and page-specific helper copy.
3. Optional sync/loading banner only while a real sync/index job is active; no placeholder whitespace when hidden.
4. Right-aligned page controls: `Settings` and `Expand all` / `Collapse all`.
5. Compact category dropdown rows, closed by default unless current behavior explicitly opens loaded state.
6. Expanded category body with compact table-like sender rows and one row action button matching Settings.
7. Bulk selection action area if selected sender staging remains available.

Do not render:

- Broad toolbar/card/pill wrappers around the cleanup controls.
- A search box on Bulk Archive/Delete.
- A page-level account selector.
- Filter-pill strips or summary-stat strips on Unread Only.
- Bottom next-step mock pills.
- Persistent `Ready to stage for Review` or equivalent status panels.

## Category Header Contract

Category headers must match the mock hierarchy:

| Surface | Left Side | Right Side |
|---------|-----------|------------|
| Bulk Archive/Delete | Category name plus short description | Sender count plus optional size |
| Unread Only | Group name plus short description | Sender count plus unread total |

Concrete structure:

- Left block uses a strong category title and muted one-line description.
- Right block uses separate metric elements, not one dense slash-delimited text blob.
- Bulk Archive/Delete metric examples: `84 senders`, `About 2.4 GB`; if size is unavailable, use `Size pending` or omit the size metric.
- Unread metric examples: `74 senders`, `2,780 unread`.
- Chevron/toggle affordance remains at the far right.
- User-created categories appear near the closest predefined category and carry visible `User generated` in the description/tag area.
- Category names are displayed as plain text only.

Category visual density:

- Remove the heavy broad pill/card enclosure feel where the mock shows each category toggle as its own compact row.
- Category rows may retain subtle left accent bars/tints if the walkthrough shows they improve scanability without making the stack feel heavy.
- Category header minimum height should feel close to the mock, not taller than necessary for the two-line left block and right metrics.

## Sender Row Contract

Bulk Archive/Delete sender rows:

| Column Order | Content |
|--------------|---------|
| Optional Select | Checkbox for selectable rows, especially Other and bulk staging |
| Sender | Display name plus sender address |
| Emails | Message count |
| Size | Estimated size when available, otherwise `Size pending` / `Unavailable` according to data truth |
| Domains | Domain |
| Action | One button matching Settings |

Unread Only sender rows:

| Column Order | Content |
|--------------|---------|
| Optional Select | Checkbox for selectable rows |
| Sender | Display name plus sender address |
| Unread | Unread count |
| Size | Estimated size when available |
| Domains | Domain |
| Type | Only where needed, e.g. Direct mail `Change type` |
| Action | One button matching Settings |

Row visual rules:

- Rows should be compact, table-like, and professionally weighted, with no broad nested cards per sender.
- Sender name is strongest; address/domain/size are secondary muted text.
- Protected senders keep a visible protected label and disabled action controls.
- Button radius should be slightly rounder than the current sharp small radius but remain aligned with local tokens: use `10px` target radius for row action buttons unless walkthrough evidence favors the existing `6px`.
- High-attention cleanup action color remains consistent across Archive, Delete, and Mark as Read; label changes but color does not.
- Responsive layout stacks fields without page-level horizontal scrolling at 375px and preserves 44px touch targets.

## Category Management Contract

Replace visible per-row internal `Correct classification` clutter with mock-aligned category-management affordances:

| Scenario | Visible Interaction |
|----------|---------------------|
| Other category on Bulk Archive/Delete | Select senders, then `Move selected` or `Create category` |
| Other category on Unread Only | Select senders, then `Move selected` or `Create category` |
| Direct mail / wrong sender type | `Change type` plain control where the mock exposes sender type correction |
| User-created category | Show `User generated` tag next to the category description/name |

Modal/dialog contract:

- Move/create flows open centered modals, not full inline workflows.
- Dialog title describes the action, e.g. `Move selected senders` or `Create category`.
- Dialog copy explains that new categories appear below the closest predefined category with `User generated`.
- Existing server-side ownership and sanitization remain required: trim whitespace, enforce length, reject control characters and HTML/script syntax, escape output, store/display plain text only.
- Category corrections remain account-owned and user-scoped; no global learning rules.

Data contract:

- `SenderCategoryGroup.userGenerated` must drive visible `User generated` tags.
- If current category summaries do not emit user-created categories, Phase 16 planning must include the data path needed to render first-class user-created category groups. This is required to satisfy UX-14.

## Staging Feedback Contract

Phase 16 removes the persistent cleanup status panel and keeps feedback at the row/button level.

Required behavior:

- Bulk Archive/Delete and Unread Only must not include `cleanup-action-result-frag :: status` or any persistent panel headed `Ready to stage for Review`.
- Staging requests still use exact materialized provider message IDs before Review item creation.
- Successful staging disables and visually mutes affected rows and controls in place.
- Button text changes to `Staged` or `Already staged`.
- No mailbox mutation occurs before Review approval.
- No redirect, new staging page, or Selection Preview page is introduced.
- Review remains the inspection and approval destination.

Accessible feedback:

- A compact live region or row/form-level status target must announce staging success/failure without creating a persistent visual panel.
- Errors should be close to the triggering row/form where feasible and must remain keyboard/focus reachable.
- Delete staging continues to require the Gmail Trash recovery acknowledgement before staging.

The exact count, scope hash, duplicate prevention, LIFO Review order, conflict checks, CSRF, ownership checks, protected-sender handling, and immutable Review scope remain behavior contracts even when the visible panel is removed.

## Bulk Unsubscribe Contract

Bulk Unsubscribe remains an individual-sender workflow, not a grouped category workflow.

Required layout:

- Rail-only account selector.
- Simple header.
- Optional real-sync loading banner only when active.
- Compact top controls: category, time duration, compact sender/domain search, and right-aligned Settings for default `Archive` or `Delete` only.
- Rows show sender/domain, email count, `Read %`, primary action, and ellipsis menu.
- Ellipsis menu includes `View stats`, `Archive all`, and `Delete all`.
- Primary row button says `Unsubscribe` when possible, otherwise `Archive` or `Delete` based on Settings. Never show a combined `Archive/Delete` label.
- Stats modal opens centered with top action buttons, incoming email distribution chart, and compact email table.

Safety:

- UI must not claim unsubscribe success until execution results are known.
- Preserve destination safety, consent, protected-sender behavior, honest accepted/pending/confirmed/failed/manual states, and bounded query performance.
- Do not add grouped categories, mark-read default action, export, CSV, snapshot, or download affordances.

## Review And Analytics Guardrails

Review:

- Remains discoverable through the text-only rail label `Review`.
- Remains LIFO by `queued_at` and `sequence` descending internally.
- Must preserve exact selected counts and delete-specific Trash recovery warning.
- Removing rail badges and cleanup status panels must not weaken Review inspection, approval, removal, conflict, or undo behavior.

Analytics:

- Remains one active account at a time.
- Must not expose export, CSV, snapshot, or download affordances in authenticated UI.
- Existing retained backend snapshot/export code, if any, is not a user-facing UI affordance.

## Audit Walkthrough Contract

UX-15 requires a page-by-page authenticated walkthrough before remediation closure.

The walkthrough artifact must include:

| Field | Meaning |
|-------|---------|
| Page | Bulk Archive/Delete, Unread Only, Bulk Unsubscribe, Review, Analytics |
| Expected mock / Build Note behavior | Specific visual or interaction contract |
| Current authenticated behavior | Observed app behavior before or during remediation |
| Severity | Blocker, must-fix, polish, or aligned |
| Remediation target | Concrete closure target |
| Closure evidence | Screenshot/note/test/manual verification after remediation |

Minimum audit focus:

- Rail labels are exact text-only labels and no visible numeric badges remain.
- Unread Only has exact helper copy and no stale notes above categories.
- Cleanup controls are right-aligned, quiet, and not wrapped in a broad toolbar card.
- Category headers show split metrics.
- Sender rows match compact table-like hierarchy and button treatment.
- Staging feedback is row/button-level only.
- Category-management controls match `Move selected`, `Create category`, and `Change type`.
- User-created categories show `User generated`.
- Bulk Unsubscribe remains individual-sender workflow.
- Review preserves exact counts, LIFO ordering, warning copy, and approval flow.
- Analytics and all workspace pages contain no export/snapshot/download affordances.
- 375x812, 200% zoom, keyboard reachability, focus states, dialogs, 44px targets, and no page-level horizontal scrolling are verified.
