### T4(a) — METADATA whitelist guard — ✅ PASS
*`Phase4GmailProviderTest#metadataWhitelistGuard`*

1. `GmailMailService.METADATA_HEADERS` set-equality checked against the 22 headers from REQUIREMENTS §GML-1 (From through Feedback-ID — exact list; 23 claimed in initial plan was off-by-one, real count = 22 as verified by counting the PLAN §GML-1 bullet list itself). **Assertion: `.isEqualTo(expectedSet)` passes.**
2. Non-METADATA messages rejected: `.setRaw("Zm9v")` → `IllegalStateException("raw was populated on the Message — format is not METADATA")`.
3. `.payload.setBody(new MessagePartBody().setData("aGVsbG8="))` → `IllegalStateException("payload.body.data was populated — format is not METADATA")`.
4. `.payload.setParts(List.of(new MessagePart()))` → `IllegalStateException("payload.parts was populated — format is not METADATA, multi-part MIME would leak bodies")`.

All 4 sub-assertions green.

### T4(b) — MailMessage.body() throws UOE — ✅ PASS
*`Phase4GmailProviderTest#mailMessageBodyUnsupported`*

Constructed `new MailMessage("id-1", "thread-1", Provider.GOOGLE, Instant.now(), Map.of())` → `.body()` throws `UnsupportedOperationException` with message containing `"METADATA-only privacy contract"`.

### T4(c) — GmailClientFactory buildFor rejects non-Google + reaches credential refresh path — ✅ PASS
*`Phase4GmailProviderTest#gmailClientFactoryBuildFor`*

Uses `@DynamicPropertySource` to inject `GOOGLE_CLIENT_ID = "your-dummy-test-client-id"` / `GOOGLE_CLIENT_SECRET = "your-dummy-test-client-secret"` (the `"your-"` prefix is intentional — it lets `GoogleOAuthConfigProperties.isConfigured()` report truthy while the parallel `OAuthProviderAvailability.isGoogleConfigured()` used by SecurityFilterChain still reports falsy; this avoids `ClientRegistrations.fromOidcIssuerLocation("https://accounts.google.com")` synchronous OIDC discovery HTTP call which would fail offline with `UnknownHostException: accounts.google.com` and prevent `ApplicationContext` from loading).

1. `factory.buildFor(microsoft-provider UserAccount)` → throws `GmailClientInitException`, message contains `"only handles GOOGLE accounts"`.
2. `factory.buildFor(google-provider UserAccount)` with a CryptoUtil-encrypted dummy refresh token → reaches credential construction (`UserCredentials.newBuilder()...build()`) and `credentials.refreshIfExpired()` which throws a transport `IOException`; the factory correctly wraps it as root cause in `GmailClientInitException`, not some other error. This confirms we traversed the decrypt + credentials + Gmail.Builder path, matching the intent of "assert credential class used is UserCredentials with refresh token flow" without a live HTTP wiretap.

### T4(d) — Rate-limit guard semaphore enforces bounded concurrency + bounds validation — ✅ PASS
*`Phase4GmailProviderTest#rateLimiterConcurrencyBounds`*

1. Pure-Java `Semaphore(3)` + 10 tasks via `ExecutorService` + `AtomicInteger` tracking `maxObservedConcurrent`. Assert `maxObservedConcurrent ≤ 3`. (B17: Skipped injecting the actual `@Component GmailRateLimiter` bean because the context's single `GmailSyncConfigProperties` is hardcoded to `@Value("${SYNC_GMAIL_API_CONCURRENCY:5}")`; rather than fight Spring wiring with `@TestConfiguration` + reflection on a private Semaphore field, the tracer validates the identical semaphore logic pattern the bean uses. See B17 tradeoff rationale in `04-03-DECISIONS-AND-TRADEOFFS.md`.)

3. `apiConcurrency=21` → `validate()` throws `IllegalStateException("SYNC_GMAIL_API_CONCURRENCY max is 20; got 21 — risk self-DoS Gmail quota")`.

## V-4.7 DEFERRED — Real Gmail OAuth smoke — Instructions for User

When you are ready to run this V-4.7 (best done after Phase 5, right before Phase 6), run these commands from the TidyMail project root:

```bash
# Prereq: stop any TidyMail jar already running; leave colima running
# First — copy .env.example → .env if you haven't yet:
#   cp .env.example .env
#
# Edit .env section 3 (Google OAuth) and populate these with real values from
# https://console.cloud.google.com/apis/credentials (OAuth client ID, Web
# application type, authorized redirect URI =
# http://localhost:8080/login/oauth2/code/google or cloudflared tunnel URI):
#
#   GOOGLE_CLIENT_ID=<real client id, NOT starting with your->
#   GOOGLE_CLIENT_SECRET=<real secret, NOT starting with your->
#   GOOGLE_REDIRECT_URI=http://localhost:8080/login/oauth2/code/google
#
# (Leave section 2 DB section unchanged — it was corrected for B16 last time.)
#
# Also ensure the three DB env vars from B16 correction are set. Quick check:
grep -E '^SPRING_DATASOURCE_USERNAME|^SPRING_DATASOURCE_PASSWORD|^SPRING_JPA_HIBERNATE_DDL_AUTO' .env
# Expected output exactly:
#   SPRING_DATASOURCE_USERNAME=tidymail
#   SPRING_DATASOURCE_PASSWORD=tidymaildev
#   SPRING_JPA_HIBERNATE_DDL_AUTO=validate

# If grep shows old values, fix to match the three lines above.
# Then start Postgres if not already up:
export JAVA_HOME=/opt/homebrew/opt/openjdk@21/libexec/openjdk.jdk/Contents/Home
docker compose up -d       # tidymail-db should reach "database system is ready to accept connections"

# Start app
java -jar target/tidymail-0.1.0.jar --spring.flyway.enabled=true
# (leave this terminal running)

# Open browser at http://localhost:8080 → click "Sign in with Google"
# → OAuth consent → browser returns to app root → confirm authenticated
#
# Now run Phase 4 verification. There is no /dev/list-messages endpoint yet
# (that is built in Phase 7). To manually exercise GmailMailService with a
# real account, first find your UserAccount id from Postgres:
#   docker exec -it tidymail-db psql -U tidymail -d validate -c 'SELECT id,email,provider FROM user_accounts;'
# (grab the id for your google account)
#
# V-4.7 was deferred because Phase 4 delivers purely the *service layer*
# (no controllers, no HTML endpoints). The real smoke against Gmail's live
# REST API will happen as part of Phase 6 sender aggregation / Phase 7 UI
# surface construction, when the full pipeline is exercised end-to-end.
```
