## V-6.8 (DEFERRED to Phase 7) Real-Gmail live API verification

Same posture as V-4.7. The user must click "Continue with Google" in a browser on localhost (or Cloudflare tunnel hostname) to complete OAuth consent. Then:

1. After successful OAuth redirect back to app, browser session should have valid principal.
2. Visit `POST /api/senders/_sync` (requires authenticated session + CSRF token, or use a browser DevTools fetch). This scans up to 5 pages × 100 messages of the user's real Gmail inbox.
3. `GET /api/senders?sort=scoreDesc&size=20` — inspect JSON in response:
   - Top senders that are real newsletters should have `bulkMarketingScore == 2 or 3` (List-Unsubscribe + aged+reply0 commonly both present).
   - `hasListUnsubscribe == true` on at least 3 senders (any real inbox has newsletter traffic).
   - Sorted by `scoreDesc`: items[0].bulkMarketingScore ≥ items[1].bulkMarketingScore.
   - `sampleMessageIds` length ≤ 5.
   - `domainRollups[0].countAcrossAllSenders` typically = work.com or gmail.com aggregation.
4. `GET /api/reply-zero?olderThanDays=3` — expected ≥ 1 item in real inbox (everyone has forgotten personal threads); `bulkSender:false` on all of them.
5. Confirm Postgres table `sender_stats` has ≥ 1 row: `psql -h localhost -p 5432 -U tidymail -d tidymail -c "SELECT count(*) FROM sender_stats;"`. (Password: tidymaildev per docker-compose.)
6. Undo: sign out to wipe all cached sender_stats + user_action rows per cascade-delete FK rule.

Until this deferred step runs, Phase 6 backend is considered functionally verified against its unit/integration contract.
